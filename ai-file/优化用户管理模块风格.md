## 🦸 obra/superpowers 技能完整指南 (14 个技能)

### 1. **brainstorming** (116.0K 安装)
**用途**：在任何创意工作前使用 - 创建功能、构建组件、添加功能或修改行为
**核心**：结构化设计对话，9 个步骤：探索上下文 → 提问 → 提出方案 → 展示设计 → 写文档 → 评审循环 → 用户批准 → 写计划

### 2. **using-superpowers** (68.8K 安装)
**用途**：任何对话开始时使用 - 建立如何查找和使用技能的规则
**核心**：要求在任何响应（包括澄清问题）前调用 Skill 工具，严格的技能优先级

### 3. **systematic-debugging** (67.2K 安装)
**用途**：遇到任何 bug、测试失败或意外行为时，在提出修复前使用
**核心**：四阶段调试流程：根因调查 → 模式分析 → 假设测试 → 实现（带测试）

### 4. **writing-plans** (68.9K 安装)
**用途**：有规范或需求的多步骤任务，在动手写代码前使用
**核心**：将规范分解为 2-5 分钟的任务，TDD 风格：写失败测试 → 验证失败 → 实现 → 验证通过 → 提交

### 5. **requesting-code-review** (57.0K 安装)
**用途**：完成任务、实现主要功能或合并前使用，验证工作是否符合要求
**核心**：派代码审查子代理，提供精确的 git 提交范围、实现细节和需求，反馈分 Critical/Important/Minor 三级

### 6. **test-driven-development** (57.7K 安装)
**用途**：实现任何功能或 bug 修复时，在写实现代码前使用
**核心**：红-绿-重构循环：先写失败测试 → 看着它失败 → 写最少代码通过 → 重构保持绿色

### 7. **executing-plans** (53.9K 安装)
**用途**：执行书面的实现计划，带关键审查和任务检查点
**核心**：加载并评审计划 → 顺序执行任务 → 按指定的验证 → 阻塞时立即停止询问

### 8. **subagent-driven-development** (48.8K 安装)
**用途**：编排专门的子代理处理任务的不同部分
**核心**：每个任务派一个新子代理 + 两阶段审查（规范合规 + 代码质量）

### 9. **verification-before-completion** (47.0K 安装)
**用途**：在声称工作完成、修复、测试通过前强制验证命令
**核心**：五步验证：识别证明命令 → 重新运行 → 读取完整输出 → 验证声明匹配证据 → 陈述结果带证据

### 10. **receiving-code-review** (45.7K 安装)
**用途**：评估代码审查反馈，避免表演式同意和盲目实现
**核心**：验证反馈 → 理解 → 评估 → 技术回应或有理由的反驳 → 按优先级逐个实现并测试

### 11. **writing-skills** (45.4K 安装)
**用途**：测试驱动的文档，创建可重用的代理技术、模式和参考指南
**核心**：先写失败测试场景 → 写最少技能文档解决特定违规 → 遵循红-绿-重构

### 12. **dispatching-parallel-agents** (43.6K 安装)
**用途**：将独立任务委托给专业代理并发工作
**核心**：每个独立问题域派一个代理，让它们并发工作，然后评审摘要并集成非冲突修复

### 13. **using-git-worktrees** (43.5K 安装)
**用途**：隔离的 git 工作树，智能目录选择和安全验证
**核心**：自动检测工作树位置 → 验证 git 忽略 → 自动项目设置 → 运行基线测试

### 14. **finishing-a-development-branch** (41.4K 安装)
**用途**：完成开发分支的结构化工作流，带测试验证和合并/PR 选项
**核心**：验证所有测试通过 → 呈现四个选项（本地合并、创建 PR、保持分支、丢弃）→ 执行选择 → 清理
